# Training & Evaluation Benchmark Derived from RULER

In this document, we describe the training and evaluation benchmark derived from RULER, which is supported by the `Ruler` data module ([ruler.py](./ruler.py)). It complements the benchmark derived from HELMET (see [helmet.md](./helmet.md)): HELMET provides data for context lengths up to 128K tokens only, while RULER can generate data for any context length. We support 8K, 16K, 32K, 64K, 128K, and 256K tokens (with K = 1,024).

RULER is a generator of synthetic long-context tasks: a short question is asked about a controlled pattern hidden in a long context. Since instances are generated, there is no limit to their number, and they are independent of each other. This makes RULER well suited for fine-tuning, in addition to evaluation. We include the four tasks of RULER which do not need additional corpora to be downloaded:

|Category	|Dataset	|Metrics	|Description	|Size	|Generation budget	|
|---	|---	|---	|---	|---	|---	|
|Retrieval	|`niah_single_1`	|string_match_all	|retrieve a number for a key hidden in a noise haystack	|(400, 100)	|128	|
|Multi-hop tracing	|`vt`	|string_match_all	|find all variables of a chain of assignments	|(400, 100)	|30	|
|Aggregation	|`cwe`	|string_match_all	|extract the 10 most common words of a numbered list	|(400, 100)	|120	|
|Aggregation	|`fwe`	|string_match_all	|extract the 3 most frequent words of a coded text	|(400, 100)	|50	|

Here, the size is (development, evaluation) for the default `num_samples=500`. The generation budget is the number of tokens RULER reserves for the answer.

Other RULER tasks are not supported: `niah_single_2`, `niah_single_3`, `niah_multikey_1`, `niah_multivalue`, `niah_multiquery` need essays as haystack, `qa_1`, `qa_2` need QA datasets. Note that HELMET contains three RULER tasks as well (`ruler_mk_needle`, `ruler_mk_uuid`, `ruler_mv`), up to 128K tokens.

We adopt the same general procedure as for HELMET:

1. **Instance construction**: Instances are generated by the original RULER code (`scripts/data/prepare.py`), pinned to a fixed commit of the [RULER repository](https://github.com/NVIDIA/RULER). We use the task arguments of `scripts/synthetic.yaml`, no chat template (`base`), and random seed 42. RULER measures lengths with the `cl100k_base` tokenizer of `tiktoken`, and the target length includes the generation budget of the task.
2. **Unified format**: Each instance is a JSON object with fields ["input", "output", "outputs", "query_id", "max_length"]. RULER splits the prompt into `input` and `answer_prefix`, we join them again. `outputs` is the list of reference strings, all of which have to be contained in the answer. `output` is the target used for training, obtained by joining `outputs` (see below).
3. **Separation of splits**: The first 100 instances form the evaluation partition, the remaining ones the development partition. Since instances are sampled independently, we do not shuffle. RULER generates the same instances for the same random seed, so the evaluation partition does not change if `num_samples` is increased.


## Data Generation

Data is generated when it is needed for the first time. The RULER repository is downloaded to `~/.cache/huggingface/ruler/` (files stored with Git LFS are downloaded separately), and generated instances are written to

```text
~/.cache/huggingface/ruler/data/
  131072/
    niah_single_1/validation.jsonl
    vt/validation.jsonl
    ...
  262144/
    ...
```

This is the layout written by RULER's `prepare.py`. If you generated data with RULER yourself, use `--data.dataset_parent_dir` to point to its root directory. The development and evaluation partitions are cached in `~/.cache/huggingface/ruler/longtrain/`. At 256K tokens, an instance needs about 1 MB on disk, so 500 instances of one task need about 0.5 GB, plus about twice as much for caches (of `datasets` and of the partitions). Use `--data.dataset_parent_dir` to store data elsewhere.

RULER needs additional dependencies:

```bash
pip install tiktoken wonderwords nltk pyyaml tqdm tenacity scipy
```

Generating 500 instances for 128K or 256K tokens takes a while. We recommend to do this before training, on a machine without GPUs, for example:

```python
from keys_values.data.load_ruler_dev_eval import generate_source_data

for max_length in ("128k", "256k"):
    for dataset_key in ("niah_single_1", "vt", "cwe", "fwe"):
        generate_source_data(dataset_key, max_length, num_samples=500)
```

After generation, the lengths of all instances are validated with the tokenizer used for generation (pass `validate=False` to skip this). `generate_source_data` also allows to use a different tokenizer for measuring lengths (`tokenizer_type`, `tokenizer_path`), or a local copy of the RULER repository (`ruler_dir`). Note that the tokenizer of your model may produce more tokens than `cl100k_base`. Use `--data.max_seq_length` to filter out sequences which are too long.

Instances are generated with `num_samples=500` (the default of RULER), but more can be used for training. For example, `--data.num_samples 1000` generates 1000 instances and uses 900 of them for the development partition.


## Usage

```bash
python3 keys_values/__main__.py finetune_long_lora \
    Qwen/Qwen3-4B-Instruct-2507 \
    --out_dir /home/ubuntu/out/finetune/ruler_vt_256k \
    --data Ruler \
        --data.dataset_key vt \
        --data.max_length 256k \
        --data.metadata_dir /home/ubuntu/out/finetune/ruler_vt_256k/data \
    --eval.use_sample_metric True \
        --eval.sample_metric_max_generated_tokens 30 \
    ...
```

All arguments of `Helmet` are supported, except for `use_old_metrics`. In addition, `--data.num_samples` sets the number of instances.

For sample-based evaluation (`--eval.use_sample_metric True`), we use the metric of RULER, `string_match_all`: the fraction of reference strings contained in the generated answer, ignoring case. `--eval.sample_metric_max_generated_tokens` should be set to the generation budget of the task (see table above). The default of 20 is too small for `cwe` and `fwe`.


## Tasks

Each instance is wrapped into one of the following instruction templates (see `get_instruction_template` in [load_ruler_dev_eval.py](./load_ruler_dev_eval.py)). For `vt` and `cwe`, RULER prepends one in-context example, which is the same template filled in, followed by its answer. For training, we join the reference strings in the same format as the answer of this example.

### Retrieval: `niah_single_1`

A single needle "One of the special magic numbers for {$KEY} is: {$VALUE}." is inserted at a random position into a haystack made of repetitions of "The grass is green. The sky is blue. The sun is yellow. Here we go. There and back again.". The key is a random adjective-noun pair, the value a random 7-digit number, which is the answer.

```
A special magic number is hidden within the following text. Make sure to memorize it. I will quiz you about the number afterwards.
{$CONTEXT}
What is the special magic number for {$QUERY} mentioned in the provided text? The special magic number for {$QUERY} mentioned in the provided text is
```

Example target: `5663623`

### Multi-hop tracing: `vt`

A chain of assignments "VAR {$X1} = {$VALUE}", "VAR {$X2} = VAR {$X1}", ... (4 hops) is inserted into the same noise haystack. The answer consists of the 5 variables which are assigned the value.

```
Memorize and track the chain(s) of variable assignment hidden in the following text.

{$CONTEXT}
Question: Find all variables that are assigned the value {$QUERY} in the text above. Answer: According to the chain(s) of variable assignment in the text above, {$NUM_V} variables are assigned the value {$QUERY}, they are: 
```

Example target: `LTVHU MGLSG IXCDJ DFKIM BVKUY`

### Aggregation: `cwe`

The context is a numbered list of words, where 10 words appear 30 times each, and the other words appear 3 times each. The answer consists of the 10 common words.

```
Below is a numbered list of words. In these words, some appear more often than others. Memorize the ones that appear most often.
{$CONTEXT}
Question: What are the 10 most common words in the above list? Answer: The top 10 words that appear most often in the list are:
```

Example target: `1. gold 2. audited 3. abuse 4. stretch 5. absorbed 6. runway 7. drudgery 8. measurement 9. compress 10. squeamish`

### Aggregation: `fwe`

The context is a sequence of random coded words, whose frequencies follow a Zipf distribution with exponent 2. The most frequent word is replaced by "...", and the answer consists of the next 3 most frequent words.

```
Read the following coded text and track the frequency of each coded word. Find the three most frequently appeared coded words. {$CONTEXT}
Question: Do not provide any explanation. Please ignore the dots '....'. What are the three most frequently appeared words in the above coded text? Answer: According to the coded text above, the three most frequently appeared words are:
```

Example target: `nwlwst rspvov hmcxdl`
